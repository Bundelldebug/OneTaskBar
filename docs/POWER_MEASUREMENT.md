# 전력 사용량 점검

2026-10-29 수정은 음량·출력 기기·밝기의 이벤트가 동작할 때 중복 조회를 줄이고, 미디어 창의 강제 소프트웨어 렌더링을 해제합니다. GPU를 사용할 수 없는 환경의 WPF 기본 대체 렌더링은 유지합니다. 프레임 제한, 효과 제거, 강제 GC나 작업 집합 축소는 적용하지 않았습니다.

## 확인한 범위

- 실제 오디오 값을 바꾸지 않는 검사에서, 같은 음량을 1,000번 읽어도 엔드포인트를 반복 조회하지 않았습니다. 종료 시 콜백이 해제되는 것도 확인했습니다.
- 미디어 펼침·접힘, 클릭 통과, 곡선 모서리, 콘텐츠·블러 동기화와 애니메이션 검사를 통과했습니다.
- 설치된 본체와 복구 프로그램의 30초 표본은 수정 전 CPU 0.0776%, 수정 후 0.0778%였습니다. 논리 프로세서 수로 정규화한 합산 값이며, 짧은 표본에서는 CPU 감소가 확인되지 않았습니다.
- 당시 미디어 세션은 활성 상태였지만 같은 영상·재생 위치를 고정한 비교가 아닙니다. 이 수치로 시간당 배터리 감소량이나 개선 비율을 계산할 수 없습니다.
- 완전 방전 기준 배터리 사용 시간과 전체 RAM 150 MiB 미만은 확인하지 못했습니다.

## 다시 측정할 때

같은 화면 밝기, 주사율, 삼성 성능 모드와 브라우저 영상을 유지한 상태에서 비교합니다. 빠른 설정이나 검사 창을 열어 둔 표본은 평상시 표본과 나눕니다. CPU와 메모리는 아래 명령으로 측정할 수 있습니다.

```powershell
./tools/Measure-Runtime.ps1 -Executable '<설치 경로>/App/OneTaskBar.exe' -Seconds 120
```

측정 중 앱이나 복구 프로세스가 재시작되면 결과를 버리고 다시 측정합니다. `live-state.json`의 `mediaPlaying`과 `audioReads`는 재생 상태와 오디오 조회 횟수를 확인하는 데 사용합니다. 로그와 측정 파일은 로컬에 저장됩니다.
